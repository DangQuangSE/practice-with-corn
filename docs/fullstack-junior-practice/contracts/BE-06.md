# BE-06 — Search and pagination contract

## Query

`GET /api/items?page=0&size=20&q=note&status=ACTIVE&from=2026-01-01&to=2026-12-31&sort=name,asc`

- Page is zero-based; default size is 20; maximum size is 100.
- Supported filters: `q`, `status`, inclusive `from`/`to` dates.
- Sort field is allowlisted (`name`, `price`, `createdAt`); direction is `asc` or `desc`.
- Invalid range, status, page, or sort values return 400 Problem Details.
- The backend applies filter/order/page in the database. It documents why it returns `Page` (exact total) or `Slice` (no count query).

## Response

`ApiEnvelope<Item[]>` with populated page metadata. The frontend mirrors filters in URL search params and renders page/sort state.

## Independent checks

- BE: use synthetic rows spanning two pages and two dates/statuses; verify page bounds and allowlist.
- FE: mock two page responses and check URL state survives refresh/back navigation.
