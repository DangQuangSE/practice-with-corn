# BE-01 — Item resource routes

**Paired workspaces:** `java-business-rules/exercises/phase-02-rest-foundations/` and `nextjs-business-rules/exercises/phase-02-next-foundations/`.

## Scenario

Expose a small catalog of synthetic items. Backend owns the API contract; frontend can use a mock until the API is ready.

## Contract

| Method | Path | Success | Main errors |
|---|---|---|---|
| GET | `/api/items` | 200 `ApiEnvelope<Item[]>` | 400 invalid query |
| GET | `/api/items/{id}` | 200 `ApiEnvelope<Item>` | 404 |
| POST | `/api/items` | 201 `ApiEnvelope<Item>` and `Location` | 400, 409 |
| PATCH | `/api/items/{id}` | 200 `ApiEnvelope<Item>` | 400, 404, 409 |

`Item`: `{ "id": "uuid", "name": "Notebook", "price": 4.50, "deleted": false }`.

`ApiEnvelope<T>`: `{ "data": T, "page": null }`. Error responses use `application/problem+json`; see [BE-04](BE-04.md).

## Independent checks

- BE: run Spring Boot and use `curl.exe -i` against one route; no persistence setup is needed for route-shape practice.
- FE: mock the documented success/error JSON and verify route behavior without Java running.
