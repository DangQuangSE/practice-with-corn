# BE-04 — Success envelope and error contract

## Success

```json
{ "data": { "id": "uuid", "name": "Notebook", "price": 4.5, "deleted": false }, "page": null }
```

Paged responses use `page: { "number": 0, "size": 20, "totalElements": 0, "totalPages": 0 }`.

## Error

Use `application/problem+json` with RFC 9457 fields `type`, `title`, `status`, `detail`, and `instance`. Validation may add a stable `errors: [{ "field": "name", "message": "must not be blank" }]` extension. Never include stack traces, SQL, Java class names, tokens, or internal hostnames.

## Independent checks

- BE: trigger a validation error and an unexpected exception; compare content type and ensure the response is generic.
- FE: render title/detail and map known `errors[].field` values; unknown error shapes get a safe fallback.
